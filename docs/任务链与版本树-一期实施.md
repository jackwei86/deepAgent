### 排错记录（有价值的一课）

验证脚本最初用正则 `任务单：`([0-9-]+)`` 提取任务单 ID 反复失败——**任务 ID 尾段是十六进制**（如 `ee71` 含字母 e），`[0-9-]` 不覆盖字母。已改为 ``任务单：`([^`]+)` ``。凡匹配任务 ID 的正则都应使用 `[^`]+` 或 `[0-9a-f-]+`。

## 任务链语义

- **pipeline_id**：处理链 ID，等于**首个任务**的 task_id，其后派生任务继承；
- **parent_task_id**：直接上游任务（素材取自其产物时自动登记）；
- 回退/分支方式：任意历史任务的产物都可作为新任务的素材 → 新任务挂在同一条链上，历史不可变、分支追加式；
- 对话级回退：Open WebUI 原生消息编辑/重新生成分支。

## 补充：撤销到"最开始(原图)"（2026-09-14）

- 场景：用户连续处理 A→B→C 后说"撤销所有处理，还原到最开始"——原图是聊天附件，没有任务单编号，一期还原无法覆盖；
- 实现：`tool_impl` 新增 `_extract_first_user_image()`（正序扫描对话，取第一张用户上传图，
  兼容 files 字段与 content 图片部件/data URL）；还原工具 `task_id` 留空时自动走该路径，
  生成内容等于原图的新任务（作为新链起点，原链保留）；
- 工具 docstring 同步教会 LLM："还原到最开始/回到原图" → task_id 留空；
- 验证：还原任务内容与原始上传图逐字节一致（filecmp），新链/原链均正确 ✅
